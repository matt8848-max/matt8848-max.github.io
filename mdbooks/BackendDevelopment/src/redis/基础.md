# 基础

## 什么是Redis

一种内存数据库，常用于缓存

## Redis架构

### 单个实例

最直接的 Redis 部署方式。缺点是怕突然实例失效，但小场景适合。

### 高可用性

设置是主从部署方式，从部署保持与主部署之间数据同步。

当数据写入主实例时，它会将这些命令的副本发送到从部署客户端输出缓冲区，从而达到数据同步的效果。

从部署可以有一个或多个实例。这些实例可以帮助扩展 Redis 的读取操作或提供故障转移，以防 main 丢失。


### Redis复制

Redis 的每个主实例都有一个复制 ID 和一个偏移量。
+ 这两条数据对于确定副本可以继续其复制过程的时间点或确定它是否需要进行完整同步至关重要。
+ 对于主 Redis 部署上发生的每个操作，此偏移量都会增加。

当 Redis 副本实例仅落后于主实例几个偏移量时，它会从主实例接收剩余的命令，然后在其数据集上重放，直到同步完成。

如果两个实例无法就复制 ID 达成一致，或者主实例不知道偏移量，则副本将请求全量同步。这时主实例会创建一个新的 RDB 快照并将其发送到副本。

复制ID用于推断此新提升的副本实例是从先前哪个主实例复制出来的。
这将决定如何进行同步。

### Redis哨兵

哨兵的单词是sentinel。

职责：
+ 监控：确保主从实例按预期工作。 
+ 通知：通知系统管理员 Redis 实例中的事件。
+ 故障转移管理：如果主实例不可用并且足够多的（法定数量）节点同意这是真的，Sentinel 节点可以启动故障转移。
+ 配置管理：Sentinel 节点还充当当前主 Redis 实例的发现服务。

### Redis集群

利用分片将数据存储在多个实例上。

Gossiping协议是用于确定集群健康状况的协议。

## Redis持久化模型

主要用于防止数据丢失。

### RDB
RDB（Redis 数据库）：RDB 持久化以指定的时间间隔执行数据集的时间点快照。

此方案是全量的服务。
可致请求瞬间延迟。
但是，恢复相对较快

### AOF
AOF（Append Only File）：AOF 持久化记录服务器接收到的每个写入操作，这些操作将在服务器启动时再次被执行，重建原始数据集。

对业务进程性能影响偏低，但是恢复慢。
