## String

String 是最基本的 key-value 结构
+ key 是唯一标识
+ value 是具体的值
    + value其实不仅是字符串
    + 也可以是数字（整数或浮点数）
    + value 最多可以容纳的数据长度是 512M。

### 内部实现

String 类型的底层的数据结构实现主要是 int 和 SDS（简单动态字符串）。

SDS与C语言的字符串不同：
+ SDS  不仅可以保存文本数据，还可以保存二进制数据。
    + SDS 使用 len 属性的值而不是空字符来判断字符串是否结束，并且 SDS 的所有 API 都会以处理二进制的方式来处理 SDS 存放在 buf[] 数组里的数据。
    + SDS 不光能存放文本数据，而且能保存图片、音频、视频、压缩文件这样的二进制数据。
+ SDS 获取字符串长度的时间复杂度是 O(1)。
    +  C 语言的字符串并不记录自身长度，所以获取长度的复杂度为 O(n)
    + SDS 结构里用 len 属性记录了字符串长度，所以复杂度为 O(1)。
+ Redis 的 SDS API 是安全的，拼接字符串不会造成缓冲区溢出。
    + SDS 在拼接字符串之前会检查 SDS 空间是否满足要求，如果空间不够会自动扩容，所以不会导致缓冲区溢出的问题。

字符串对象的内部编码（encoding）有 3 种 ：int、raw和 embstr。

+ 如果一个字符串对象保存的是整数值，并且这个整数值可以用long类型来表示，那么字符串对象会将整数值保存在字符串对象结构的ptr属性里面（将void*转换成 long），并将字符串对象的编码设置为int。
+ 如果字符串对象保存的是一个字符串，并且这个字符申的长度小于等于 32 字节（redis 2.+版本），那么字符串对象将使用一个简单动态字符串（SDS）来保存这个字符串，并将对象的编码设置为embstr， embstr编码是专门用于保存短字符串的一种优化编码方式。
+ 如果字符串对象保存的是一个字符串，并且这个字符串的长度大于 32 字节（redis 2.+版本），那么字符串对象将使用一个简单动态字符串（SDS）来保存这个字符串，并将对象的编码设置为raw。

embstr 编码和 raw 编码的边界在 redis 不同版本中是不一样的：
+ redis 2.+ 是 32 字节
+ redis 3.0-4.0 是 39 字节
+ redis 5.0 是 44 字节

embstr的好处：
+ embstr编码将创建字符串对象所需的内存分配次数从 raw 编码的两次降低为一次
+ 释放 embstr编码的字符串对象同样只需要调用一次内存释放函数
+ 因为embstr编码的字符串对象的所有数据都保存在一块连续的内存里面可以更好的利用 CPU 缓存提升性能。

embstr的缺点：
+ 如果字符串的长度增加需要重新分配内存时，整个redisObject和sds都需要重新分配空间
+ embstr编码的字符串对象实际上是只读的，redis没有为embstr编码的字符串对象编写任何相应的修改程序

### 常用指令

普通字符串操作
```bash
127.0.0.1:6379> SET name lin
OK
127.0.0.1:6379> GET name
"lin"
127.0.0.1:6379> EXISTS name
(integer) 1
127.0.0.1:6379> STRLEN name
(integer) 3
127.0.0.1:6379> DEL name
(integer) 1
```

批量设置
```bash
127.0.0.1:6379> MSET key1 val1 key2 val2
OK
127.0.0.1:6379> MGET key1 key2
1) "val1"
2) "val2"
```

计数器
```bash
127.0.0.1:6379> SET num 0
OK
127.0.0.1:6379> INCR num
(integer) 1
127.0.0.1:6379> INCRBY num 10
(integer) 11
127.0.0.1:6379> DECR num
(integer) 10
127.0.0.1:6379> DECRBY num 10
(integer) 0
```

过期设置（默认永不过期）：
```bash
# 设置 key 在 60 秒后过期（该方法是针对已经存在的key设置过期时间）
127.0.0.1:6379> EXPIRE num 60
(integer) 1
127.0.0.1:6379> TTL num
(integer) 55
#设置 key-value 类型的值，并设置该key的过期时间为 60 秒
127.0.0.1:6379> SET key val EX 60
OK
127.0.0.1:6379> SETEX key 60 value
OK
```

不存在就插入：
```bash
127.0.0.1:6379> SETNX key value
(integer) 0
#等原本的过期了之后
127.0.0.1:6379> SETNX key value
(integer) 1
```

### 应用场景

+ 缓存对象
+ 计数器
+ 分布式锁（利用不存在才插入特性加锁，利用lua脚本实现锁释放）
+ 共享 Session 信息（即共享登陆信息）

## List

List 列表是简单的字符串列表，按照插入顺序排序，可以从头部或尾部向 List 列表添加元素。

列表的最大长度为 2^32 - 1，即每个列表支持超过 40 亿个元素。

### 内部实现
在 Redis 3.0 版本中，List 类型的底层数据结构由双向链表或压缩列表实现：
+ 如果列表的元素个数小于 512 个（默认值，可由 list-max-ziplist-entries 配置），列表每个元素的值都小于 64 字节（默认值，可由 list-max-ziplist-value 配置），Redis 会使用压缩列表作为 List 类型的底层数据结构
+ 如果列表的元素不满足上面的条件，Redis 会使用双向链表作为 List 类型的底层数据结构；

从 Redis 3.2 到 Redis 7.0，List 类型使用 quicklist：它把多个紧凑容器通过双向链表连接起来，每个节点可以保存多个列表元素。

Redis 7.0 之前，节点内部使用压缩列表（ziplist）

从 Redis 7.0 起，普通的 packed 节点内部改用 listpack。

Redis 7.2 中，小型 List 还可以直接使用一个 listpack，超过 list-max-listpack-size 控制的大小或元素数量限制后，再转换成 quicklist。

因此，listpack 既可以直接作为 List 的底层编码，也可以作为 quicklist 节点内部的容器。

### 常用命令

```bash
# 将一个或多个值插入到 key 列表表头（最左边），最后的值在最前面
LPUSH key value [value ...]
# 将一个或多个值插入到 key 列表表尾（最右边）
RPUSH key value [value ...]

# 移除并返回 key 列表的头元素
LPOP key
# 移除并返回 key 列表的尾元素
RPOP key

# 返回列表 key 中指定区间内的元素，区间以偏移量 start 和 stop 指定，从 0 开始
LRANGE key start stop

# 从 key 列表表头弹出一个元素，没有就阻塞 timeout 秒
BLPOP key [key ...] timeout
# 从 key 列表表尾弹出一个元素，没有就阻塞 timeout 秒
BRPOP key [key ...] timeout
```

### 应用场景
+ 消息队列：消息保序、处理重复的消息和保证消息可靠性
    + 消息保序，一边push，另一边pop即可。利用BRPOP防止一直询问
    + 处理重复：list不保证，需要设计者自己实现全局id
    + 可靠性：设计者准备两个list，使用BRPOPLPUSH来备份弹出的消息，来保证可恢复性
    + list不支持消息组
    + 建议使用stream来作为消息队列
