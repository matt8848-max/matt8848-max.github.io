# 算法的基本概念

算法只是一些指导你如何正确编写高性能代码的内容。
当然一个算法就像一个函数一样，有输入输出，不过它还有操作对象。

## 性能分析

首先性能分析常用的是数学上与极限相关的符号。
符号如下

**渐近上界\\(O(g(n))\\)**：

\\(O(g(n))\\)={\\(f(n):存在c>0和n_0>0,使得对所有n\geq n_0，有0\leq f(n)\leq cg(n)\\)}

例如，插入排序在最坏情况下，\\(f(n)=an^2+bn+c=O(n^2)，g(n)=n^2\\)

**渐近下界\\(\Omega(g(n)) \\)**：

\\(\Omega(g(n))\\)={\\(f(n):存在c>0和n_0>0,使得对所有n\geq n_0，有0\leq cg(n) \leq f(n)\\)}

例如，插入排序在最好情况下(已经排好序)，\\(f(n)=\Omega(n)，g(n)=n\\)

**渐近确切界\\(\Theta(g(n))\\)**
包含**渐近上界**和**渐近下界**：

\\(\Theta(g(n))\\)={\\(f(n):存在c_1>0，c_2>0，n_0>0,使得对所有n\geq n_0，有0\leq c_1g(n)\leq f(n)\leq c_2g(n)\\)}

例如对于任意的\\(f(n)=an^2+bn+c=\Theta(n^2)，a>0\\)，可取\\(c_1=\frac{a}{4}，c_2=\frac{7a}{4}，n_0=2max(\frac{|b|}{a},\sqrt \frac{|c|}{a})\\)来形式化证明

**上界\\(o(g(n))\\)**：

\\(o(g(n))\\)={\\(f(n):存在c>0和n_0>0,使得对所有n\geq n_0，有0\leq f(n)\lt cg(n)\\)}

例如，\\(f(n)=n=o(n^2)，g(n)=n^2\\)

**下界\\(\omega(g(n))\\)**：

\\(\omega(g(n))\\)={\\(f(n):存在c>0和n_0>0,使得对所有n\geq n_0，有0\leq cg(n) \lt f(n)\\)}

例如，\\(f(n)=n^2=\omega(n)，g(n)=n\\)



但是，这些符号有个问题，会隐藏常数且过于理论化，会导致，有时极限上来讲更慢的算法在实际场景中更快。

例如来自leetcode的[220题](https://leetcode.cn/problems/contains-duplicate-iii/description/)存在两种解决方案。(k是窗口大小)
+ 方案一：滑动窗口+有序序列+二分查找，时间复杂度是\\(O(n\log_2 min(n,k))\\)
+ 方案二：滑动窗口+桶排序+hash表+溢出处理，时间复杂度是\\(O(n)\\)

这两种方案的速度差不多。

## 简单算法分析

```rust
// 双层 for 循环：外层固定一个位置，内层扫描其余元素并交换，整体是 O(n²)
fn sort(mut data: Vec<i32>) -> Vec<i32> {
    for i in 0..data.len() {
        for j in i + 1..data.len() {
            if data[j] < data[i] {
                data.swap(i, j);
            }
        }
    }
    data
}

fn main() {
    let data = vec![5, 2, 9, 1, 7, 3, 8, 0, 6, 4]; // 长度为 10
    println!("{:?}", sort(data));
}
```

以一个双层for循环代码为例。
显然是一个\\(O(n^2)\\)的代码。

```rust
// 单层 for 循环：只遍历一次即可完成，整体是 O(n)
fn max(data: &[i32]) -> i32 {
    let mut best = data[0];
    for &x in data {
        if x > best {
            best = x;
        }
    }
    best
}

fn main() {
    let data = vec![5, 2, 9, 1, 7, 3, 8, 0, 6, 4]; // 长度为 10
    println!("{}", max(&data));
}
```

以此单循环代码为例，它的运行时间显然要更短，且为\\(O(n)\\)

## 涉及概率的分析

假如：你需要雇佣一名办公助理，面试需要花钱，雇佣并辞掉旧助理需要花钱，每面试到更优秀的就进行雇佣并辞退旧助理。
```rust
// 直接可运行：mdbook 支持隐藏行——以 `#` 开头的行会参与编译/运行，但渲染时被隐藏
fn hire_assistant(assistants: &Vec<usize>) {
    let mut best = 0;
    for (index, candidate) in assistants.iter().enumerate() {
        println!("interview");
        if candidate > &assistants[best] {
            best = index;
            println!("hire");
        }
    }
}

# fn main() {
#     hire_assistant(&vec![3, 1, 4, 1, 5, 9, 2, 6]);
# }
```

+ 最坏情况：我们面试了每一个人，且面试对象以质量严格递增，导致我们进行了assitants.len()次hire
+ 最好情况：我们面试了每一个人，且面试对象以质量严格递减，导致我们进行了1次hire

计算方法非常简单：

在给定一个样本空间S和一个事件A下，事件A的指示器随机变量I{A}为
\begin{align}
I\\{A\\}=\begin{cases}
1&如果A发生\\\\
0&如果A不发生
\end{cases}
\end{align}
根据期望的性质，指示器随机变量具有如下性质：
\begin{align}
E[X_A]&=E[I\\{A\\}] \\\\
&=1 \times P\\{A\\} + 0 \times P\\{\bar A\\}\\\\
&=P\\{A\\}
\end{align}

对应雇佣问题的**平均情况**：

首先定义指示器随机变量\\(X_i=I\\{第i个被聘用\\}\\)，**此处从1开始计数**
\begin{align}
E[X]&=E[\sum_{i=1}^{n} X_i]\\\\
&=\sum_{i=1}^{n} E[X_i]\\\\
&=\sum_{i=1}^{n} \frac{1}{i}\\\\ 
&=\ln n + O(1)
\end{align}

尽管我们面试了n个人，但平均起来，实际上大约只雇佣了\\(\ln n\\)个人。


## 递归式分析

方法很多，例如递归树和主定理。

主定理的推理比较麻烦。递归树比较直观，比较适合树状的情况。

主定理如下：


若有递归式形如
\\[T(n)=aT(\frac{n}{b})+f(n)\\]
其中\\(a\geq1\\)和\\(b>1\\)为常数，\\(f(n)\\)为渐近正函数


那么有3种直接有结论的情况：
1. 若存在\\(\epsilon \gt 0\\)使得\\(f(n)=O(n^{log_b {a-\epsilon}})\\)，则\\(T(n)=\Theta(n^{\log_b a})\\)
2. 若\\(f(n)=\Theta(n^{\log_b a})\\)，则\\(T(n)=\Theta(n^{\log_b a}\log_2 n)\\)
3. 若存在\\(\epsilon >0\\)使得\\(f(n)=\Omega(n^{log_b {a+\epsilon}})\\)，且存在常数\\(c<1\\)和足够大的n使得\\(af(\frac{n}{b})\leq cf(n)\\)，则\\(T(n)=\Theta(f(n))\\)

**注意**：3种情况并未完全覆盖所有情况，大小比较必须是多项式意义上的

例如：
\\[T(n)=9T(\frac{n}{3})+n\\]
**解**：
+ \\(a=9,b=3,f(n)=n\\)
+ 则\\(n^{\log_b a}=\Theta(n^2)\\)
+ 符合情况1，\\(T(n)=\Theta(n^2)\\)


## 摊还分析

在摊还分析中，我们求数据结构的一个操作序列中所执行的所有操作的平均时间，来评价操作的代价。 这样，我们就可以说明一个操作的平均代价是很低的，即使序列中某个单一操作的代价很高。 摊还分析不同于平均情况分析，并不涉及概率，可以保证最坏情况下每个操作的平均性能。

学习这部分内容时，记住在摊还分析中所赋予的费用仅仅是用于分析，不需要出现在实际程序中。

摊还分析有三个主要的方法：
+ 聚合分析
+ 核算法
+ 势能法
我们采用一个例子来讲解三个方法。

假设我们有一个栈，它有如下操作：
+ PUSH：将对象压入栈，O(1)
+ POP：将对象弹出栈，O(1)
+ MULTIPOP(S,k)：它删除栈S栈顶的k>0个对象，如果栈中的对象数少于k，则将整个栈的内容弹出

单次操作时间代价：
+ PUSH：O(1)
+ POP：O(1)
+ MULTIPOP(S,k)：\\(min\\{S.len(),k\\}\\)

我们考虑一下由PUSH，POP和MULTIPOP组成的n个操作序列在空栈上操作的情况。

### 聚合分析
虽然MULTIPOP的代价可能很高，但是对于只有n个操作的序列在空栈上操作，代价至多为\\(O(n)\\)。

一个对象被压入栈后，至多有一次弹出。因此至多执行POP的次数(包含MULTIPOP里的POP)至多与PUSH次数相同。
从而可以得知，总体的时间代价为\\(O(n)\\)，平均代价为\\(O(1)\\)。
此处我们设每个操作的摊还代价为平均代价\\(O(1)\\)。

### 核算法
当摊还代价大于实际代价时，我们将差额存入特定的对象，并称为**信用**。
对于后续操作时，实际代价大于摊还代价时，用信用来支付差值。

+ 我们必须小心选择操作的摊还代价。
+ 我们需要确保总摊还代价给出了总真实代价的上界。
+ 对于任意n个操作构成的序列，用\\(c_i\\)表示第i个的真实代价，\\(\hat c_i\\)表示摊还代价，则应当有
\\[\sum_{i=1}^{n}\hat c_i \geq \sum_{i=1}^{n} c_i\\]
最后我们存储的信用正好为\\(\sum_{i=1}^{n}\hat c_i - \sum_{i=1}^{n} c_i\\)。
+ 由不等式可知，我们需要一直保持信用为非负值。

我们赋予一些摊还代价。

|   操作   | 实际代价 | 摊还代价 |
|:--------:|:--------:|:--------:|
|   PUSH   |     1    |     2    |
|    POP   |     1    |     0    |
| MULTIPOP | min(k,s.len()) |     0    |

对于由PUSH、POP、MULTIPOP组成的长度为n的操作序列操作一个初始为空的栈，总摊还代价为\\(O(n)\\)。
进一步知实际总代价也是\\(O(n)\\)。

### 势能法
在势能法中，摊还分析不在将预支付的代价视为信用，而是表示为势能。

势能法如下：
+ 我们将对一个初始数据结构\\(D_0\\)执行n个操作。
+ 对每个\\(i=1,2,3,\dots,n\\)，令\\(c_i\\)为第i个操作的实际代价，令\\(D_i\\)为在数据结构\\(D_{i-1}\\)上执行第i个操作得到的结果数据结构。
+ 势函数Φ将每个数据结构\\(D_i\\)映射到一个实数\\(\Phi(D_i)\\)，此值即为关联到数据结构\\(D_i\\)的势。
第i个操作的摊还代价\\(\hat c_i\\)用势函数Φ定义为：
\\[\hat c_i =c_i+\Phi(D_i)-\Phi(D_{i-1})\\]
因此，每个操作的摊还代价等于其实际代价加上因操作引起的势能变化。
+ 总摊还代价为：
\\[\sum_{i=1}^{n}\hat c_i=\sum_{i=1}^{n}(c_i+\Phi(D_i)-\Phi(D_{i-1}))=\sum_{i=1}^{n}c_i +\Phi(D_n)-\Phi(D_0)\\]
+ 如果能定义一个势能函数Φ，使得\\(\Phi(D_n)\geq \Phi(D_0)\\)，则总摊还代价\\(\sum_{i=1}^{n}\hat c_i\\)给出了总实际代价\\(\sum_{i=1}^n c_i\\)的一个上界。
+ 在实际中，我们并不知道n为多少，因此实际要求\\(\Phi(D_i)\geq \Phi(D_0)\\)。
同时，通常简单的定义\\(\Phi(D_0)=0\\)

注意：
不同的Φ可能会产生不同的摊还代价，但是它们都是上界。

**回到例子**

+ 我们定义势函数为其中对象的数量，因此\\(\Phi(D_i)\geq 0=\Phi(D_0)\\)。
+ 如果第i个操作为PUSH，那么势能摊还代价为：
\\[\hat c_i=c_i+\Phi(D_i)-\Phi(D_{i-1})=1+(lenght+1)-length=2\\]
+ 如果第i个操作为MULTIPOP，将\\(k'=min(k,length)\\)个对象弹出栈，那么势能摊还代价为：
\\[\hat c_i=c_i+\Phi(D_i)-\Phi(D_{i-1})=k'-k'=0\\]
+ 同理，POP为0
+ 每个操作的摊还代价都是O(1)，因此，总的摊还代价为\\(O(n)\\)，n个操作的最坏情况时间为\\(O(n)\\)。

### 动态表
这是一个更为复杂的例子。

有时，我们无法预知到底需要多大的空间将对象存储于表中，此时我们使用动态表来动态的分配空间。

当我们进行插入和删除时，可能会引起表的扩张和收缩，从而有较高的实际代价，但我们将空闲空间相对于总空间的比例永远不超过一个常量分数，则它们的摊还代价都是O(1)。

我们将表T的**装载因子**定义为：
\begin{align}
\alpha(T)=\begin{cases}
1&分配的空间=0\\\\
\frac{使用的空间}{分配的空间}&分配的空间\neq 0
\end{cases}
\end{align}

#### 表扩张
我们先分析**只能插入**的情况。

我们假定T就是一个总规模固定的数组。
当装载因子达到1的时候插入(即表满的时候，**某些数据结构里，表满不为因子等于1**)，我们需要进行扩张。

一个常用的启发式策略是，扩张的时候将总规模扩大至2倍。
此时会保证**装载因子**总是保持在0.5以上。
(很多人都知道这个策略但是总是会因为单次的高代价而忽略总体其实并不高)

示例代码如下（代码库里没有）
```rust
/// 使用vec代替，其实vec的底层和本节有很多相似之处,size记录总规模  
/// 着重注意size
fn table_insert<T>(table: &mut Vec<T>, x: T, size: &mut usize) {
    // 特殊情况
    if *size == 0 {
        *size = 1;
    }
    // 长度相同
    if &table.len() == size {
        *size *= 2;
        // 手动的需要在此重新申请一个table，将数据从旧的复制过来，然后释放旧的table
    }
    table.push(x);
}
```

我们假定一次插入的代价为1。
每次插入一个新的元素x会有1的代价。
如果进行了表扩张，那么从旧表复制到新表需要额外增加当前size的代价。
具体点，我们对空表执行n个插入的操作。
第i个插入的代价为\\(c_i\\)，显然没有扩张时\\(c_i=1\\)，扩张时\\(c_i=i\\)。
\begin{align}
c_i=\begin{cases}
i&若i-1为2的幂\\\\
1&其它
\end{cases}
\end{align}

粗看，最坏的总运行时间上界为\\(O(n^2)\\)，但是并不确切。
因为在实际上，扩张是很少的。

因此实际的总代价为
\\[\sum_{i=1}^{n}c_i\leq n+\sum_{j=0}^{\lfloor \log_2 n \rfloor}2^j\lt n+2n=3n\\]
摊还代价为3。

我们用**势能法**做一个相同的分析。

定义势函数Φ，在扩张操作之后其值为0，而表满的时候其值为表的规模。
\\[\Phi(T)=2\times T.num-T.size\\]
T.num为实际的元素数，T.size为总的规模

我们令\\(num_i\\)为第i个操作后表中数据项的数量，\\(size_i\\)表示第i次操作后的总规模，\\(\Phi_i\\)表示第i个操作后的势。
我们有\\(num_0=0,size_0=0,\Phi_0=0\\)

+ 若第i个操作没有触发扩张，那么
\begin{align}
\hat c_i&=c_i+\Phi_i-\Phi_{i-1}\\\\
&=1+(2num_i-size_i)-(2num_{i-1}-size_{i-1})\\\\
&=1+(2num_i-size_i)-(2(num_i-1)-size_i)\\\\
&=3
\end{align}
+ 若第i个操作触发了表扩张，那么
\begin{align}
\hat c_i&=c_i+\Phi_i-\Phi_{i-1}\\\\
&=num_i+(2num_i-size_i)-(2num_{i-1}-size_{i-1})\\\\
&=num_i+(2num_i-2(num_i-1))-(2(num_i-1)-(num_i-1))\\\\
&=3
\end{align}

#### 表扩张和收缩

为了防止，删除的时候会有大量的空间浪费，那么选择当因子低于某个值的时候，进行表收缩。
此处我们选择收缩的条件为因子小于0.25。

我们需要一个新的势函数，它在因子为1或0.25时为T.num，因子为0.5时为0。
\begin{align}
\Phi(T)=\begin{cases}
2T.num-T.size&若\alpha(T)\geq \frac{1}{2}\\\\
\frac{T.size}{2}-T.num &若\alpha(T)\lt \frac{1}{2}
\end{cases}
\end{align}

1. 第i个操作为插入，\\(\alpha_{i-1}\geq \frac{1}{2} \\)：此时同前文，\\(\hat c_i=3\\)至多为3
2. 第i个操作为插入，\\(\alpha_{i-1}\lt \frac{1}{2} \\)：
\begin{align}
\hat c_i&=c_i+\Phi_i-\Phi_{i-1}\\\\
&=1+(\frac{size_i}{2}-num_i)-(\frac{size_{i-1}}{2}-num_{i-1})\\\\
&=1+(\frac{size_i}{2}-num_i)-(\frac{size_{i}}{2}-(num_{i}-1))\\\\
&=0
\end{align}
3. 第i个操作为插入，\\(\alpha_{i-1}\lt \frac{1}{2} ,\alpha_i\geq \frac{1}{2}\\)：
\begin{align}
\hat c_i&=c_i+\Phi_i-\Phi_{i-1}\\\\
&=1+(2num_i-size_i)-(\frac{size_{i-1}}{2}-num_{i-1})\\\\
&=1+(2(num_{i-1}+1)-size_{i-1})-(\frac{size_{i-1}}{2}-num_{i-1})\\\\
&=3num_{i-1}-\frac{3}{2}size_{i-1}+3\\\\
&=3\alpha_{i-1}size_{i-1}-\frac{3}{2}size_{i-1}+3\\\\
&\lt \frac{3}{2}size_{i-1}-\frac{3}{2}size_{i-1}+3\\\\
&=3
\end{align}

因此插入的摊还代价至多为3。

同理可分析删除，结论为常数上界。

因此总的n个插入、删除序列的运行时间为O(n)。
